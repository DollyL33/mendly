The core rule. Claude writes plans and gives verdicts. Plain code catches reused photos and decides whether money moves. PayPal holds, takes and pays.

How a repair flows

Follow one action: Marco sends proof

  1. components/ProofCapture.tsx: Marco picks a photo per item (camera, or a sample set) and the browser sends them to the server.
  2. app/api/jobs/[id]/proof/route.ts: the server claims the job (so a double click can't run twice), saves each photo, and runs the checks in order.
  3. lib/photos.ts → fingerprint, findReuse: a 64-bit difference hash; a near-identical earlier photo fails, whatever the AI says.
  4. lib/ai.ts → inspectProof: each photo goes to Claude as base64 with its checklist item; the answer must fit a JSON schema (pass/fail, reason, fix).
  5. lib/rules.ts → decide: plain code chooses retake, Linda, or pay. lib/payment.ts then captures the hold and sends the payout.

A practice to reuse next time

Prove the riskiest unknown first, with a tiny script. Before any screens, check-paypal.ts held, took and paid out real sandbox money. Everything after built on something already known to work.

Let the AI judge, let code decide. Whenever an AI's answer leads to an action that matters (money, access, deletion), have it return a fixed-shape verdict, and put the decision in plain code you can test.
